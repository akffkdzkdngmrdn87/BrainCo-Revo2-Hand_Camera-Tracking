# tests — 검증 스크립트

| 파일 | 장비 필요 | 무엇을 검증하는가 |
|---|---|---|
| `제스처_검증.py` | 없음 (인터넷만) | 정답을 아는 손동작 **실사진**으로 손가락 위치값이 맞게 나오는지 |
| `실기_구동시험.py` | 로봇 + 24V | 보낸 값과 로봇에서 **되읽은 실제 위치**를 대조 |

계산 논리 자체 검증은 본체에 들어 있습니다.

```bash
python3 src/hand_tracking_control.py --self-test
```

## 제스처_검증.py

위키미디어 공용의 자유 이용 저작물 손동작 사진을 내려받아,
**"펴야 하는 손가락의 평균 < 굽혀야 하는 손가락의 평균"** 이 성립하는지 검사합니다.
사람마다 다른 절대 가동범위와 무관한 기준이므로 보정 상태에 흔들리지 않습니다.

```bash
python3 tests/제스처_검증.py                # 사진 자동 내려받기 포함
python3 tests/제스처_검증.py --no-download  # 이미 받아둔 사진만 사용
```

### 시험 자료를 고를 때의 함정 (실측으로 확인)

1. **해상도가 낮으면 안 됩니다.** 25×75 픽셀 아이콘을 넣었더니 손 검출은 성공하는데
   손가락이 뒤바뀐 값이 나왔습니다. 4배 확대하면 정답이 됩니다.
   → `ensure_min_size()` 로 반드시 확대해서 넣습니다.
2. **평면 일러스트는 안 됩니다.** MediaPipe 는 실제 손 사진으로 학습된 모델이라
   음영도 질감도 없는 벡터 그림에서는 확대해도 관절 위치를 신뢰할 수 없습니다.
   → 합격 판정에는 **실사진만** 사용하고, 일러스트는 참고 표시만 합니다.

## 실기_구동시험.py

명령을 보냈다는 것과 로봇이 움직였다는 것은 다릅니다. 전송 함수가 예외 없이 끝나도
전원이 없거나 모터가 걸려 있으면 손은 그대로입니다.

```bash
python3 tests/실기_구동시험.py
# 포트 권한이 아직 반영되지 않았다면
sg dialout -c "python3 tests/실기_구동시험.py"
```

### 판정을 폄과 쥠으로 나눈 이유

**폄(0) 방향에는 방해가 없습니다.** 손가락이 벌어지는 쪽이라 서로 부딪히지 않으므로
정확히 도달해야 하고, 못 하면 진짜 고장입니다. 시작·종료 시의 안전 동작과도 직결됩니다.

**쥠(1000) 방향은 손가락끼리 맞닿습니다.** 엄지는 접힌 손가락 위에 얹혀 더 못 들어가고,
주먹에서는 검지마저 엄지에 막힙니다. 그러므로 '목표까지 갔는가'가 아니라
'충분히 움직였는가(400 이상)'로 봅니다. 그렇게 하지 않으면 정상 동작을 영영
'불일치'로 표시하게 되어 시험이 쓸모없어집니다.
