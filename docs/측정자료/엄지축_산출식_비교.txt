[문제]
  로봇의 '엄지보조'는 엄지를 손바닥 쪽으로 돌리는 축(대립/회전)이다.
  사람 손에는 이에 대응하는 '굽힘'이 없다. 카메라 좌표에서 무엇을 재야 하는가?

[정답 기준] 저장소 hand_keyboard.py 의 GESTURES 프리셋이 정한 엄지보조 값
      주먹 1000 / 브이 1000 / OK 750 / 보 0 / 엄지 척 0

[후보]
  A  엄지 중수골(1→2) 과 손목→검지MCP(0→5) 가 이루는 각
  C  엄지 방향(2→4) 과 손등 MCP 줄(5→17) 이 이루는 각
  D  엄지끝(4)과 소지MCP(17) 사이 거리 / 손바닥 길이
  E  엄지끝(4)과 검지MCP(5) 사이 거리 / 손바닥 길이
  F  엄지끝을 MCP 줄 방향으로 투영한 위치 / 손바닥 길이
  그리고 기준선으로 --thumb-aux follow (엄지보조 = 엄지) 를 함께 평가한다.

[판정 방법 — 왜 '분리도'가 아니라 '오차'인가]
  처음에는 '두 무리가 갈리는가(분리도)'로 재려 했으나, 그 기준은 잘못이다.
  분리만 되면 되는 것이 아니라 **프리셋 값에 얼마나 가까운 숫자를 내는가**가 중요하다.
  (실제로 후보 F 는 분리는 가장 잘 됐지만 부호가 반대라 값은 정반대로 나왔다.)
  그래서 각 후보에 '관측 최대=0 / 관측 최소=1000' 이라는 최적 보정을 준 뒤
  프리셋과의 절대오차를 잰다. 각 후보에 가장 유리한 조건이므로 공정하다.

[해석]
  1. 어떤 후보도 OK 사인을 맞히지 못한다. 최상위인 C 도 133 을 내놓아
     프리셋 750 과 617 만큼 어긋난다. follow 도 152 로 마찬가지다.
     사람 눈에는 OK 의 엄지가 '벌어져' 보이지만, 로봇은 엄지를 안으로 돌려야
     검지와 맞닿기 때문이다. **이 값은 사람 손 기하가 아니라 로봇 기구학이 정한다.**
     → 2D 카메라 한 대로는 원리적으로 복원할 수 없다는 것이 결론이다.

  2. 그 한계 안에서 순위를 보면
       C (평균 167) < D (177) < follow (226)
     차이가 작고 표본이 5장뿐이라, 통계적으로 유의하다고 말할 수 없다.
     D 는 최대오차가 393 으로 가장 작아 '크게 틀리는 일이 없다'는 장점이 있다.
     F 는 분리는 잘 되지만 부호가 반대여서 값이 정반대로 나온다(평균 828).

[최종 설계 결론]
  기본값은 --thumb-aux follow, 즉 엄지보조 = 엄지.

  숫자만 보면 C 가 근소하게 낫지만, 그 차이가 표본 5장 안의 잡음과 구분되지 않는다.
  반면 follow 를 뒷받침하는 근거는 측정과 독립적이고 훨씬 단단하다.

    근거 1. 이 저장소 hand_keyboard.py 의 제스처 9개 중 7개에서 엄지보조 == 엄지 이고,
            나머지 2개도 OK +150, 하트 +100 차이뿐이다.
              보 0=0 / 주먹 1000=1000 / 브이 1000=1000 / 엄지척 0=0 /
              총 0=0 / 러브 0=0 / 숫자3 1000=1000 / OK 600≠750 / 하트 500≠600
    근거 2. 제3자 독립 구현 szwedk/brainco-revo2-hand-control 의 engine/protocol.py
            POSES 에서도 open·fist·point·peace·gun·claw·three·rock·thumbs 가 모두 일치한다.
            (이 파일은 배열 순서 [thumb, thumb_aux, index, middle, ring, pinky] 와
             0=열림 / 1000=닫힘 규약도 독립적으로 확인해 준다)
    근거 3. follow 는 엄지와 엄지보조가 함께 움직인다. 두 축이 따로 놀아
            엄지가 어정쩡한 자세로 걸리는 일이 구조적으로 생기지 않는다.

  기하 추정이 필요하면 --thumb-aux geom (후보 C 식), 고정하려면
  --thumb-aux fixed --aux-fixed N 을 쓴다.
