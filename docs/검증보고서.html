1. 결론 요약

기존 코드는 "미검증"이 아니라, 현행 환경에서 실행 즉시 중단되는 상태였다. 저장소는 이 기능을 미검증으로 표기하고 있었으나, 실제로는 첫 줄에서 AttributeError 로 죽는다. 원인은 아래 ①이다.
#결함확인 방법등급
① mediapipe.solutions.hands 사용 — 현행 mediapipe 1.x 에서 이 모듈이 삭제되었다 이 PC 에 mediapipe 1.0.1 설치 후 실행 → AttributeError: module 'mediapipe' has no attribute 'solutions' 치명
② 손가락 배열이 틀렸다. [엄지,검지,중지,약지,소지,손목] 로 되어 있으나 확정값은 [엄지,엄지보조,검지,중지,약지,소지] 같은 저장소 hand_keyboard.py 와, 제3자 독립 구현 szwedk/brainco-revo2-hand-control 의 engine/protocol.py 가 일치 치명
③ 굽힘 계산이 (1.5 − 손끝거리/뿌리거리) × 1000 같은 임의 상수식이라 손 크기·카메라 거리에 따라 값이 달라진다 같은 자세의 손을 3배로 확대하면 결과가 달라짐. 관절 각도 방식은 동일 값 유지(자체시험 [4]) 중대
④ cv2.putText 로 한글 출력 — OpenCV 기본 폰트는 ASCII 전용 화면에 ??? 로 깨진다. Pillow 로 교체 중대
⑤ 로봇과 ROS 2 가 둘 다 있어야만 실행된다 — 검증 자체가 불가능한 구조 "미검증" 상태가 고착된 근본 원인 중대
조치 결과 — 웹캠에 손을 보이면 Revo2 가 실제로 따라 움직인다 전면 재작성하여 웹캠 / 영상파일 / 사진 3가지 입력과 모의 / ROS 2 / SDK직접 3가지 출력을 지원하게 했다. 장비가 하나도 없어도 --self-test 로 계산 논리를 검증할 수 있다. 로봇 실기 구동까지 확인 완료(4.5절). 남은 미검증은 ROS 2 백엔드 하나뿐이며, 경로 A(SDK 직접)로 같은 일을 할 수 있다.

2. 조사 — 무엇을 근거로 판단했는가

2.1 MediaPipe 레거시 API 의 지원 종료

구글은 2023년 3월, MediaPipe 의 기존 Legacy Solutions(mp.solutions.*) 지원을 종료하고 MediaPipe Tasks API 로 이관했다. 기존 코드가 쓰던 mp.solutions.hands 가 여기에 해당한다. 당시에는 경고만 나왔으나, 이 PC 에 설치된 mediapipe 1.0.1 에서는 mediapipe.solutions 속성 자체가 존재하지 않는다. 

$ python -c "import mediapipe as mp; mp.solutions.hands"
AttributeError: module 'mediapipe' has no attribute 'solutions'

따라서 현행 표준인 mediapipe.tasks.python.vision.HandLandmarker 로 교체했다. Tasks API 는 모델 파일(hand_landmarker.task, 7.8MB)이 코드와 별도이므로, 내려받기 절차를 설치 스크립트에 넣었다.

2.2 손가락 배열 순서 — 두 출처의 독립 일치

배열 순서는 자료마다 달라 혼선이 있던 항목이다. 서로 무관한 두 구현이 동일하게 지정한다.

출처배열값 규약
본 저장소 src/hand_keyboard.py [엄지, 엄지보조, 검지, 중지, 약지, 소지]0 = 폄, 1000 = 쥠
제3자 szwedk/brainco-revo2-hand-control
engine/protocol.py		 [thumb, thumb_aux, index, middle, ring, pinky] POS_MIN 0 = fully open,
POS_MAX 1000 = fully closed
기존 hand_tracking_control.py [엄지, 검지, 중지, 약지, 소지, 손목] 오류 —
이 오류가 실제로 일으키는 증상 '엄지보조' 자리에 검지 값이 들어간다. 검지를 굽히면 엄지가 회전하고, 그 뒤 모든 손가락이 한 칸씩 밀린다. 여섯 번째 칸에는 존재하지 않는 '손목' 값이 들어간다.

3. 재작성 설계와 그 근거

3.1 굽힘을 어떻게 잴 것인가 — 거리비에서 관절각으로

기존 방식은 손끝과 손목 사이 거리를 뿌리 관절과 손목 사이 거리로 나눈 비율에 1.5, 2.0, 500, 1000 같은 상수를 곱했다. 이 값은 손 크기와 카메라 거리에 따라 달라진다.

바꾼 방식은 관절 각도다. 관절이 굽은 각도는 손이 크든 작든, 멀든 가깝든 같다.

축계산비고
검지·중지·약지·소지 MCP·PIP·DIP 세 관절 각의 가중평균 (0.30 / 0.45 / 0.25) PIP(둘째 마디)가 굽힘을 가장 잘 나타내므로 크게 반영
엄지굽힘MCP·IP 두 관절 각의 평균관절이 하나 적고 가동폭이 좁다
엄지벌림엄지 방향(2→4)과 손등 MCP 줄(5→17)이 이루는 각 중수골 기준선은 굽지 않아 안정적

로봇의 엄지 칸은 굽힘 0.55 + 벌림 0.45 로 섞는다. 사람이 주먹을 쥘 때 엄지는 '굽는다'기보다 '손바닥 쪽으로 모이기' 때문이다. 굽힘만 쓰면 주먹인데도 값이 474 에 그쳤고, 섞으니 616 으로 개선되었다.

가동범위는 넓히기만 하고 좁히지 않는다 사람마다 손 가동범위가 다르므로, 실행 중 기준을 벗어나는 각이 나오면 자동으로 넓힌다. 좁히기는 넣지 않았다. 자동 축소를 넣으면 손을 가만히 두었을 때 기준폭이 계속 오그라들어, 미세한 떨림이 0~1000 전체로 증폭된다. 기준을 다시 잡으려면 실행 중 c 키를 누른다.

3.4 엄지보조(대립축) — 2D 카메라로는 복원되지 않는다

로봇의 엄지보조는 엄지를 손바닥 쪽으로 돌리는 축이다. 사람 손에는 대응하는 '굽힘'이 없어, 무엇을 재야 할지 정해야 했다. 기하 지표 5가지와 follow(엄지와 동일)를 실사진 5장으로 비교했다. 각 후보에 가장 유리한 보정을 준 뒤 저장소 프리셋과의 절대오차를 쟀다.

후보주먹
기대 1000		브이
기대 1000		OK
기대 750		 보
기대 0		엄지척
기대 0		평균오차최대오차
C 엄지방향각10008891331090167617
D 소지MCP거리10006074280169177393
follow (엄지와 동일)74291115272115226598

핵심은 순위가 아니라, 어떤 후보도 OK 사인을 맞히지 못한다는 점이다. 최상위 C 도 133 을 내놓아 프리셋 750 과 617 만큼 어긋난다. 사람 눈에는 OK 의 엄지가 '벌어져' 보이지만, 로봇은 엄지를 안으로 돌려야 검지와 맞닿기 때문이다. 이 값은 사람 손 기하가 아니라 로봇 기구학이 정한다. 2D 카메라 한 대로는 원리적으로 복원할 수 없다.

따라서 기본값은 --thumb-aux follow(엄지보조 = 엄지)로 정했다. 숫자상 C(167)가 follow(226)보다 근소하게 낫지만 표본 5장 안의 잡음과 구분되지 않는 반면, follow 를 뒷받침하는 근거는 측정과 독립적이고 더 단단하다.

  • 본 저장소 hand_keyboard.py 의 제스처 9개 중 7개에서 엄지보조 == 엄지. 나머지 2개도 OK +150, 하트 +100 차이뿐이다.
  • 제3자 구현 szwedk/.../protocol.py 의 POSES 에서도 open·fist·point·peace·gun·claw·three·rock·thumbs 가 모두 일치한다.
  • 엄지와 엄지보조가 함께 움직여, 두 축이 따로 놀아 엄지가 어정쩡한 자세로 걸리는 일이 없다.

원자료: 결과/엄지축_산출식_비교.txt

3.5 안전 설계

  • 시작할 때와 끝날 때 반드시 손을 편다(전 손가락 0). 저장소 전체의 규칙과 같다.
  • 손을 놓치면 마지막 자세를 유지하다가 --relax-timeout(기본 3초) 뒤 스스로 편다.
  • 연결 실패·중단·예외 어느 경로로 끝나도 finally 에서 손을 펴고 포트를 닫는다.
  • 떨림 억제 3중: 지수이동평균 → 1회 최대 변화량 제한 → 불감대(모터 채터링 방지).
  • 전송률 제한(기본 20Hz). SDK 백엔드는 큐에 가장 최신 목표 하나만 두어 명령이 밀리지 않는다.

4.4 로봇 실기 구동 — 명령을 보낸 것과 로봇이 움직인 것은 다르다

전송 함수가 예외 없이 끝나도, 전원이 없거나 모터가 걸려 있으면 손은 그대로다. 그래서 보낸 값과 로봇에서 되읽은 실제 위치를 대조했다 (--readback 옵션, tests/실기_구동시험.py).

(1) 프리셋 제스처 7종 구동 — 7/7 통과

5. 작업 중 발견한 함정

함정 1 — 입력 해상도가 낮으면 오류 없이 '조용히 틀린 값'이 나온다 위키미디어의 손동작 아이콘 원본은 25×75 픽셀이었다. 그대로 넣었더니 손 검출은 성공하는데 손가락이 뒤바뀐 값이 나왔다.
가리키기 아이콘검지중지약지소지해석
원본 25×7594787888599검지가 굽고 소지가 폄 — 완전히 반대
4배 확대101893952934검지만 폄 — 정답
→ ensure_min_size() 를 넣어, 짧은 변이 320픽셀 미만이면 확대하도록 했다 (--min-size). 웹캠에서는 발동하지 않는다.
함정 2 — 평면 일러스트는 검증 자료로 쓸 수 없다 MediaPipe 는 실제 손 사진으로 학습된 모델이다. 음영도 질감도 없는 벡터 그림에서는 확대해도 관절 위치를 신뢰할 수 없다. 처음에 일러스트로 시험했을 때 3건이 '통과'했는데, 이는 우연이었다. → 판정 자료를 실사진만으로 교체했다.
함정 3 — OpenCV 가 실패한 카메라를 FFMPEG 로 열어 '정상'이라 보고한다 cv2.VideoCapture(1) 은 V4L2 로 실패한 뒤 조용히 FFMPEG 로 되돌아가 메타데이터 전용 장치인 /dev/video1 을 '사용 가능'으로 보고했다. → 백엔드를 cv2.CAP_V4L2 로 명시하고, 실제로 한 프레임을 읽어 본 뒤 판정하도록 고쳤다.
함정 4 — mediapipe 1.0.1 은 종료 중 예외를 뱉는다 HandLandmarker 를 명시적으로 닫지 않고 인터프리터가 내려가면 __del__ 안에서 TypeError: 'NoneType' object is not callable 역추적이 출력된다. → 연결 실패로 중단되는 경로까지 포함해 항상 먼저 close() 하도록 했다.
함정 5 — 작업 스레드에서 사라지는 예외 SDK 백엔드는 별도 스레드에서 asyncio 루프를 돌린다. SDK 폴더가 없을 때 그 스레드에서 난 예외가 본 스레드에 전달되지 않아, 20초를 기다린 뒤 "시간 초과"라는 엉뚱한 진단을 냈다. → 예외를 잡아 즉시 전달하도록 고쳤다. 지금은 0.5초 안에 정확한 원인을 알려 준다.
함정 6 — 계정이 dialout 그룹에 없으면 포트가 아예 안 열린다 로봇을 붙였는데 /dev/ttyUSB0 이 보이는데도 열리지 않았다. toprobot 이 dialout 그룹에 없어서였다(읽기·쓰기 권한 모두 False). 
sudo usermod -aG dialout $USER
그룹 변경은 다음 로그인부터 반영된다. 재로그인 없이 바로 쓰려면 sg dialout -c "<명령>" 으로 새 셸을 띄운다. 실행_웹캠_로봇.sh 는 이 상황을 스스로 판단해 처리한다.
함정 7 — SDK 가 닫힌 이벤트 루프로 콜백을 넣는다 SDK 는 내부(Rust) 스레드에서 파이썬 asyncio 루프로 콜백을 넣는다. asyncio.run() 은 코루틴이 끝나는 즉시 루프를 닫으므로, 뒤늦게 도착한 콜백이 RuntimeError: Event loop is closed 역추적을 뱉었다. → 루프를 직접 만들어 실행하고, 끝난 뒤 0.3초 더 돌려 잔여 콜백을 배출한 다음 닫도록 고쳤다. 루프 종료 시점의 예외는 예외 처리기로 삼킨다.
함정 8 — 영상 파일은 로봇보다 훨씬 빨리 재생된다 40.8초짜리 영상이 이 PC 에서 16초 만에 처리됐다. 화면만 볼 때는 상관없지만 로봇을 붙이면 손가락이 물리적으로 움직일 시간보다 명령이 빨리 도착해 동작이 뭉개진다. → --pace 를 넣어, 로봇에 연결됐을 때는 원래 속도(초당 프레임 수)로 늦춘다. 적용 후 42.7초로 원본과 맞았다.
참고 — 무해한 경고 QFontDatabase: Cannot find font directory ... 는 OpenCV 의 Qt 백엔드 경고로 동작에 영향이 없다. Feedback manager requires a model with a single signature inference, Using NORM_RECT without IMAGE_DIMENSIONS 도 MediaPipe 의 정상 동작 중 경고다.

6. 제조사 SDK 저장소의 이관

공식 SDK 저장소가 이관되었다. 새 저장소에는 MIT 라이선스가 있다.
저장소상태LICENSE
BrainCoTech/stark-serialport-example (구) 내용은 남아 있으나 README 는 이관 안내 없음
BrainCoTech/brainco-hand-sdk (신) 현행 유지 대상. python/revo2/revo2_utils.py 등 구조 동일 MIT
구 저장소 주소를 안내하는 문서를 아직 쓰고 있다면 새 주소로 갱신해야 한다.

본 검증에는 새 저장소(MIT)를 ~/brainco-hand-sdk 에 내려받아 사용했고, bc-stark-sdk 는 2.0.5 를 가상환경 안에만 설치했다. 이전 판(0.9.5)에서 메이저 버전이 올라갔으나, set_finger_positions_and_durations · set_finger_unit_mode · FingerUnitMode.Normalized · modbus_close 등 이 프로그램이 쓰는 API 는 그대로 존재한다(실행으로 확인).

※ 제조사 SDK 는 본 저장소에 포함하지 않는다. 이용자가 위 배포처에서 직접 내려받는다. 라이선스 관계는 저작권_출처.md 참조.
