| 파일 | 규격 | 용도 |
|---|---|---|
| `손추적_시연.webp` | 애니메이션 WebP · 720×1280 · 12 fps · 412프레임 · 9.0 MB | **대문 자동 재생용.** 상대경로로 바로 표시됩니다 |
| `손추적_시연.mp4` | H.264 · 1080×1920 · 30 fps · 34.3초 · 6.9 MB · 무음 | 원본 화질. 내려받기용 |

## 영상 내용

**웹캠 손추적으로 로봇손을 실제로 구동하는 장면을 한 화면에 담은 것입니다.**

* 위쪽 모니터 — `src/hand_tracking_control.py` 의 실행 창.
  웹캠 영상 위에 21개 관절 골격(노란 선·초록 점)과 손가락 6축 값(0~1000)이 그려집니다.
* 아래쪽 — 받침대에 놓인 실제 BrainCo Revo2 Basic 로봇손.
* 사람이 손을 폈다 쥐었다 하면 **로봇이 같은 자세를 따라 합니다.**

프로그램 창 하단 상태줄의 `출력=sdk` 는 모의가 아니라 **로봇에 실제로 명령을 보내는 중**임을 뜻합니다.
인물의 얼굴은 포함되지 않았습니다.

### 음성 처리

원본에는 음성 트랙이 있었으나 평균 −44.2 dB · 최대 −18.6 dB 의 환경음 수준이었습니다.
배포본은 **음성을 제거**했습니다(`-an`). WebP 는 규격상 음성을 담지 않습니다.

## ⚠ 시연용 영상을 검증 입력으로 쓰면 안 됩니다

`손추적_시연.mp4` 와 `손추적_시연.webp` 에는 **이미 골격선과 수치가 그려져 있습니다.**
그것을 다시 손추적의 입력으로 넣으면 그림이 손을 가려 검출률이 2%대로 떨어집니다(실측).
검증에는 반드시 주석이 없는 `시험입력_짧은판.mp4` 를 쓰십시오. 이 파일은 검출률 100% 입니다.

```bash
# 맞음
python3 src/hand_tracking_control.py --source media/시험입력_짧은판.mp4

# 틀림 — 주석이 그려진 영상이라 검출이 안 됩니다
python3 src/hand_tracking_control.py --source media/손추적_시연.mp4
```

## 인코딩 규격의 근거

| 판 | 이유 |
|---|---|
| **WebP 를 대문에 쓴다** | GitHub 는 저장소에 커밋한 `media/*.mp4` 를 상대경로로 참조해도 **플레이어를 만들지 않습니다.** 애니메이션 WebP 는 `<img>` 로 그대로 표시되므로, 별도 절차 없이 대문에서 바로 움직입니다 |
| **H.264 / yuv420p** | HEVC(H.265)는 다수 브라우저의 `<video>` 요소에서 재생이 보장되지 않습니다 |
| **10 MB 미만** | GitHub 무료 플랜의 첨부 한도 — 영상 10 MB, 이미지·GIF 10 MB. git 커밋 한도(100 MB 하드 / 50 MB 경고)와는 별개입니다 |
| **`-movflags +faststart`** | moov 원자를 파일 앞에 두어 전체를 내려받기 전에 재생이 시작됩니다 |

## 대문에서 바로 재생되는 플레이어를 넣으려면

`user-attachments` 주소만 플레이어가 됩니다. 이 주소는 **웹 편집기에 파일을 끌어다 놓는 순간**
발급되며, 저장소에 커밋한 파일 경로로는 만들 수 없습니다. 절차는 저장소 밖의
`올리는_방법.md` §5 에 있습니다. WebP 만으로도 대문은 완성되므로 선택 사항입니다.

## 다시 만들기

원본 영상을 바꾸었을 때 세 파일을 한 번에 다시 만듭니다.

```bash
bash media/다시만들기.sh <원본영상.mp4>
```
