# 웹캠으로 손을 따라 로봇손 움직이기 — 윈도우 10 원클릭

웹캠에 손을 비추면 **로봇손(BrainCo Revo2)이 그대로 따라 움직입니다.**

---

## 두 번 누르면 끝입니다

| 누를 파일 | 무엇을 하는가 |
|---|---|
| **로봇손_따라하기.bat** | ★**이것이 본래 기능입니다.** 웹캠으로 손을 인식해 로봇손을 움직입니다 |
| **환경조사.bat** | ★**안 될 때 이것부터.** 이 컴퓨터를 통째로 조사해 원인을 짚어 줍니다 |
| **연결진단.bat** | 카메라와 포트만 빠르게 확인합니다 |
| **웹캠만_보기.bat** | 로봇 없이 화면에만 그립니다 (연습·시연용) |
| **작은창으로_따라하기.bat** | ★**전체 화면이 안 되면 이것.** 예전처럼 작은 창으로 돌립니다 |

**로봇손_따라하기.bat 은 실행 전에 이 컴퓨터를 스스로 조사합니다.**
카메라 번호도 COM 번호도 사람이 알 필요가 없습니다. 못 찾으면 **왜 못 찾았는지**
가려서 알려 줍니다 — 드라이버가 없는 것인지, 케이블·전원 문제인지.

**처음 한 번만** 인터넷에서 필요한 것을 내려받습니다(3~10분, 약 300MB).
그다음부터는 곧바로 시작합니다.

파이썬이 없으면 **자동으로 설치**합니다. python.org 에서 3.12 를 받아
**내 계정에만** 넣으므로 관리자 권한이 필요 없습니다.

화면은 **전체 화면으로 뜹니다.** 창으로 보고 싶으면 **f** 를 누르십시오(다시 누르면 전체 화면).
끝낼 때는 영상 창을 클릭하고 **q** 를 누르거나 창을 닫으십시오.

## 준비물 — 이 셋이 있어야 로봇이 움직입니다

1. **웹캠** (노트북 내장도 됩니다)
2. **로봇손 + USB 케이블**
3. ★**24V DC 어댑터** — USB 는 통신 전용이라 **전원 없이는 아무 응답이 없습니다.**
   가장 흔한 실패 원인입니다.

## 처음 할 일 — 연결진단.bat

로봇손_따라하기 전에 **연결진단.bat** 을 한 번 눌러 보십시오. 이렇게 나옵니다.

```

  카메라 0번  사용 가능  해상도 640x480  → --source 0

② 로봇손이 붙을 포트를 찾습니다
  1개를 찾았습니다:
    COM3

**둘 다 나와야** 로봇이 손을 따라 움직입니다.

- 카메라가 안 나오면 → 웹캠을 꽂고, 줌·팀즈 등이 쓰고 있는지 확인
- **포트가 안 나오면 → ★24V 어댑터부터** 확인

## ★드라이버 — 먼저 자동으로 해 보고, 안 되면 직접 받으시면 됩니다

**로봇손_따라하기.bat 을 누르기만 하면 됩니다.** 드라이버가 없으면 이렇게 물어봅니다.

```
  로봇손 드라이버를 설치하시겠습니까?
    찾은 장치 : FT231X USB UART   VID:0403 PID:6015
    칩       : FTDI FT231X USB UART  ← BrainCo Revo2 로봇손
    설치할 것 : FTDI VCP 드라이버

  ★관리자 권한 창이 뜹니다. 「예」를 눌러 주셔야 설치됩니다.

  설치할까요? (y = 예 / 그 밖 = 아니오):
```

**y** 를 누르면

1. 먼저 **윈도우 업데이트**로 시도합니다 (파일을 받지 않아 가장 안전합니다)
2. 안 되면 **제조사 공식 사이트**(ftdichip.com)에서 설치 파일을 받아 실행합니다
3. 설치가 끝나면 **USB 를 다시 꽂으라고** 알려 드리고, 다시 살펴본 뒤 바로 실행합니다

**관리자 권한 창(UAC)은 사람이 승인해야 합니다.** 프로그램이 대신 누르지 않습니다 —
드라이버는 시스템에 등록되는 것이라 그렇게 만들면 안 됩니다.

받은 파일은 실행하기 전에 **정말 압축 파일인지·크기가 맞는지·안에 설치 파일이
있는지** 확인합니다. 공식 도메인이 아니면 아예 받지 않습니다.

> **로봇손이 쓰는 칩**: FTDI FT231X (VID 0403 · PID 6015).
> 이 칩의 드라이버가 없으면 장치는 USB 에 보이는데 **COM 포트가 안 생깁니다.**
> 2026-09-10 에 실제로 이것 때문에 막혔습니다.

## 화면에 나오는 손 이름(왼손/오른손)이 반대일 때

**`h` 키를 누르십시오.** 누를 때마다 다음으로 바뀝니다.

```
자동  →  바꿈  →  그대로  →  자동 ...
```

| 값 | 무엇 |
|---|---|
| **자동** (기본) | 거울 모드면 되돌립니다. **보통 이것으로 맞습니다** |
| 바꿈 | 항상 뒤집습니다 |
| 그대로 | MediaPipe 가 낸 값을 손대지 않습니다 |

처음부터 정하려면 실행할 때 `--손좌우 바꿈` 처럼 줍니다.

> **왜 이런 일이 생기나** — 화면은 쓰기 편하도록 **거울 모드**로 보여 줍니다
> (내 손과 화면이 같은 쪽으로 움직입니다). 그런데 MediaPipe 는 **화면에 보이는
> 모양 그대로** 좌우를 판정하기 때문에, 거울을 걸면 왼손을 오른손이라고 부릅니다.
> 그래서 거울을 걸었을 때는 프로그램이 **되돌려서** 실제 손 이름으로 보여 줍니다.
>
> 2026-09-22 실측: 같은 영상을 좌우만 뒤집어 넣으니 판정이 360프레임 전부 뒤집혔습니다.
> **손가락 움직임(로봇 제어)에는 영향이 없습니다** — 이름 표시와 기록에만 쓰입니다.

### 자동으로 안 되면 — 직접 받아 설치하십시오

**드라이버는 끝까지 대신 깔아 드리지 않습니다.** 관리자 권한이 필요하고 배포 주소가
바뀌기도 해서, 자동으로 안 될 때는 **받는 곳을 알려 드리는 편이 안전합니다.**
그때는 프로그램이 브라우저를 열어 주고, 화면에 손으로 설치하는 방법을 단계별로 보여 줍니다.

| 받는 곳 | 무엇 |
|---|---|
| <https://ftdichip.com/drivers/vcp-drivers/> | **통신 칩 드라이버(FTDI VCP)** — 로봇손이 COM 포트로 잡히게 해 준다 |
| <https://www.brainco-hz.com/docs/revolimb-hand/en/revo2/download.html> | **로봇손 제조사(BrainCo) 공식 자료실** — 드라이버·SDK·설명서 |
| <https://github.com/BrainCoTech/brainco-hand-sdk> | 제조사 SDK 저장소 (이 꾸러미에 이미 들어 있습니다) |

설치 순서
1. 위 첫 줄에서 **Windows (Desktop)** 의 setup executable 을 받습니다
2. 받은 zip 을 **압축 풀기** 합니다
3. 푼 폴더의 `CDM...exe` 를 두 번 눌러 설치합니다 — 대개 이것으로 끝납니다
4. 안 되면 **장치 관리자**(Win + X)에서 노란 느낌표의 `FT231X USB UART` 를
   오른쪽 클릭 → 드라이버 업데이트 → **「내 컴퓨터에서 드라이버 찾아보기」**
   (자동 검색이 아닙니다) → ②에서 푼 폴더 지정 → 「하위 폴더 포함」 체크
5. **USB 를 뽑았다 다시 꽂고** 프로그램을 다시 실행합니다

## 안 될 때 — 환경조사.bat 이 원인을 가려 줍니다

「포트가 없다」는 말만으로는 무엇을 고칠지 알 수 없습니다. 그래서 **USB 버스까지
내려가** 장치를 VID/PID 로 식별하고, 세 가지를 구분해 알려 줍니다.

| 판정 | 뜻 | 해야 할 일 |
|---|---|---|
| **준비됨** | 쓸 포트가 있다 | 바로 실행됩니다 |
| **드라이버필요** | USB 로는 보이는데 COM 이 안 생겼다 | **어느 드라이버인지와 받는 곳을 알려 줍니다** |
| **장치이상** | 장치가 오류 상태다 | 장치 관리자에서 노란 느낌표 확인 |
| **장치없음** | USB 에도 안 보인다 | 케이블·USB 포트·24V 전원 확인 (충전 전용 케이블 주의) |

예를 들어 CH340 칩이 드라이버 없이 꽂혀 있으면 이렇게 나옵니다.

```
  판정 : 드라이버필요
  USB 로는 보이는데 COM 포트가 만들어지지 않았습니다.

    · USB-SERIAL CH340   VID:1A86 PID:7523
      칩       : QinHeng CH340/CH341
      필요한 것: CH340 드라이버
      받는 곳  : https://www.wch-ic.com/downloads/CH341SER_EXE.html
```

조사 내용은 **`환경조사.txt`** 로도 저장됩니다. 막히면 이 파일을 보내 주십시오.

## ★카메라 번호도 COM 번호도 몰라도 됩니다

**아무것도 입력하지 않아도 프로그램이 스스로 찾습니다.**
카메라와 포트를 차례로 확인한 뒤 시작합니다.

```
  쓸 수 있는 카메라를 찾습니다 ...
  ✔ 카메라를 찾았습니다: 0번 (640x480, DirectShow)
  로봇손이 붙은 포트를 찾습니다 ...
  ✔ 포트를 찾았습니다: COM3
```

여러 개가 보이면 목록을 띄우고 **번호만 누르면** 됩니다.
하나도 없으면 무엇을 확인해야 하는지 알려 주고 멈춥니다.

카메라는 **DirectShow → MediaFoundation → 자동** 순서로 시도합니다.
윈도우는 장치마다 되는 방식이 달라서, 한 가지만 쓰면 멀쩡한 카메라를
「없다」고 잘못 판단합니다.

## ★COM 번호를 몰라도 됩니다

**아무것도 입력하지 않아도 프로그램이 스스로 찾습니다.**

- 포트가 **하나**면 → 묻지 않고 그것을 씁니다
- 포트가 **여럿**이면 → 이렇게 물어봅니다. 번호만 누르면 됩니다

```
  포트가 3개 보입니다. 로봇손이 붙은 것을 고르십시오.
  (블루투스나 가상 포트가 함께 보일 수 있습니다)

    1) COM1
    2) COM3
    3) COM7

  번호 [1-3] (그냥 엔터 = 1번):
```

- 포트가 **하나도 없으면** → ★24V 어댑터부터 확인하라고 알려 주고 멈춥니다

굳이 직접 지정하고 싶으면 명령 프롬프트에서 이렇게 할 수 있지만,
**보통은 필요 없습니다.**

```
로봇손_따라하기.bat --port COM3
```

## ★화면은 전체 화면으로 뜹니다

동작을 모니터로 확인하기 좋도록 **처음부터 전체 화면**으로 시작합니다.
영상 창을 클릭한 상태에서 아래 키를 쓰십시오.

| 키 | 하는 일 |
|---|---|
| **f** | 전체 화면 ↔ 창 전환 |
| **q** | 끝내기 |
| **c** | 손 가동범위 다시 재기 |
| **space** | 잠깐 멈춤 |
| **o** | 로봇손 펴기 |

화면 비율은 유지하므로 **얼굴이나 손이 옆으로 늘어나지 않습니다.**

카메라는 **1280x720 을 먼저 요청하고, 안 되면 640x480 으로 내려갑니다.**
전체 화면에서는 640x480 을 늘려 놓으면 흐릿해지기 때문입니다.
카메라가 720p 를 지원하지 않아도 그냥 동작합니다.

처음부터 창으로 띄우고 싶거나 해상도를 직접 정하고 싶으면
명령 프롬프트에서 이렇게 할 수 있습니다(**보통은 필요 없습니다**).

```
로봇손_따라하기.bat --windowed
로봇손_따라하기.bat --cam-size 640x480
```

### 전체 화면 때문에 실행이 안 되면

**`작은창으로_따라하기.bat`** 를 누르십시오. 위 두 가지를 미리 붙여 놓은 것으로,
**전체 화면을 쓰지 않고 640x480 으로만 돌립니다.**

전체 화면을 위해 카메라에 720p 를 요청하는데, **웹캠에 따라 이 요청 뒤로
영상을 아예 내주지 않는 것이 있습니다.** 지금은 요청이 실패하면 카메라를
다시 열어 원래 크기로 되돌리므로 이런 일이 없어야 하지만, 그래도 문제가
생기면 이 파일로 예전과 똑같이 동작시킬 수 있습니다.

## 웹캠이 없어도 시험할 수 있습니다

동봉한 짧은 영상으로 손추적만 돌려 볼 수 있습니다(로봇은 움직이지 않습니다).

```

bat 에 인자를 붙이려면 명령 프롬프트에서 실행하거나, 바로 가기를 만들어
«대상» 뒤에 붙이십시오.

## 폴더 이름에 한글이 있어도 됩니다

윈도우에서 **MediaPipe 는 경로에 한글이 있으면 모델 파일을 못 엽니다**
(`Unable to open file at ... errno=-1`). 2026-09-10 에 실제로 이것 때문에
막혔습니다. 지금은 파일 내용을 파이썬이 읽어 넘기므로 **경로가 관여하지
않습니다.** 바탕화면처럼 한글이 섞인 곳에 두어도 됩니다.

원인을 바로 알 수 있습니다.

## 리눅스판과 다른 점

같은 본체 파일을 쓰고, 운영체제에 따라 갈라지는 곳만 다릅니다.

- **카메라** — 리눅스 V4L2, 윈도우 DirectShow.
  윈도우에는 V4L2 가 아예 없어 그대로 두면 카메라가 열리지 않습니다.
- **카메라 목록** — 리눅스는 `/dev/video*`, 윈도우는 번호를 차례로 열어 봅니다.
- **로봇 포트** — 리눅스 `/dev/ttyUSB0`, 윈도우 `COM3`.
- **글꼴** — 윈도우는 맑은 고딕을 먼저 찾습니다.
- **ROS 2 연동은 리눅스 전용**이라 윈도우 판에는 넣지 않았습니다.
